# Detailed knowledge contract template

Status: draft. One canonical owner per concept; no independent review inferred.

## Identity and purpose

Stable concept ID; name and aliases; owner; domain; problem answered; audience; scope exclusions; date, edition and jurisdiction if relevant.

## Prerequisites and definitions

Link prior concepts. Define every symbol, unit, cash-flow timing, currency, probability measure, accounting boundary and data observation/publication convention. Explain the idea without requiring the reader to retrieve a textbook.

## Method

State equations or a complete stepwise procedure. Explain or derive the material steps. List assumptions, identifiability/calibration conditions, admissible input domain, constraints and numerical conventions. Separate competing method variants.

## Evidence

Map each material claim to primary evidence with the exact inspected section and review depth. Record contradictory results and inaccessible material. A book name or abstract does not justify a full derivation.

## Examples and boundaries

Include an independently calculated worked case, interpretation, edge/limit cases, dimensional and reconciliation checks, and failure modes. Conceptual methods require explanatory cases rather than fabricated formulas. Distinguish model uncertainty from numerical error.

## Review and implementation

Record author review, independent domain review, mathematical example verification and implementation validation separately. Link implementation and data contracts only when assessed. Specify what future change would invalidate dependent uses.

## Relationships

Prerequisites; alternatives; aliases; downstream uses; open questions. Other articles link here instead of reproducing the canonical definition.
